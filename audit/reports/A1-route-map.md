## Mount anomalies

| finding | detail |
|---|---|
| **Nested-then-flat splits (intentional)** | Same resource addressed two ways, mounted in order so nested paths win: `schedule-patterns` (`routes/index.ts:73-77`), `shifts` (`81-84`), `commitments` (`55-59`), `time-entries` (`89-90`), `timesheets` (`91-92`), `expenses` (`111-112`), `handoff-notes` (`126-127`). Flat routers use id-scoped ownership lookups; nested routers use `authWithValidation` + service membership. |
| **PTO prefix mount** | `ptoRoutes` mounted at `/households/:householdId` (`routes/index.ts:120`) alongside other household routers; router calls `next()` when paths don't match (`ptoRoutes.ts:23-27`). Paths: `/carers/:carerId/pto/balance`, `/carers/:carerId/pto/ledger`, `/pto/mark-paid`. |
| **Literal-before-param ordering** | `householdRoutes`: `/invites/redeem`, `/invites/:code/preview` before `/:householdId` (`householdRoutes.ts:43-58`). `availabilityRoutes`: `/me` before `/:userId` (`availabilityRoutes.ts:51-63`). `timeEntryRoutes`: `/running`, `/clock-in`, `/retroactive` before `/:id` (`timeEntryRoutes.ts:40-57`). `householdShiftRoutes`: `/extra` before `/:shiftId/events` (`householdShiftRoutes.ts:37-46`). `householdHandoffRoutes`: `/recap` before `/` (`householdHandoffRoutes.ts:28-36`). |
| **Parallel day-thread surfaces** | `GET /households/:householdId/shifts/:shiftId/events` (`householdShiftRoutes.ts:45`) vs `GET /households/:householdId/day-thread` (`dayThreadRoutes.ts:16`) — different scopes (shift-scoped vs household-date), not duplicates (`dayThreadRoutes.ts:3`). |
| **No double mounts** | Each router in `routes/index.ts` is mounted once; `usersRoutes`, `jobRoutes`, `appStatusRoutes` each mounted once in `app.ts`. |
| **No orphaned route files** | All files under `apps/api/src/domains/*/routes/` are imported in `routes/index.ts` or `app.ts`. |
| **Param naming** | `:id` used for time entries and timesheets in flat routers; `:householdId`/`:childId`/`:carerId` in nested mounts — no shadowing across routers because mounts differ. `availability/:userId` vs `:carerId/busy` share one segment but second route requires `/busy` suffix (`availabilityRoutes.ts:63,72`). |
